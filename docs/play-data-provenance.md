# Play data provenance

This doc explains where the plays in `data/plays/` come from, what `verification_status` does and doesn't mean, and how to read `source_notes`.

## Two kinds of plays

The library currently contains exactly one kind of play. There are two kinds the project should eventually distinguish:

### 1. Generic-football plays (what we have today)

Plays drafted from real-world football knowledge — coaching texts, web research, training data, X&O Labs / CougCenter / Throw Deep Publishing / etc. These plays describe the **football concept** correctly: e.g. Mesh has two crossers at 6 yd, Buck Sweep pulls both guards, Triple Option reads the EDGE for dive then the force defender for pitch.

What they are NOT: extracted from a specific game's built-in playbook. The play `singleback-trio-mesh` is "Mesh as a football concept run from a Singleback Trio formation," not "the Mesh play that ships in Madden 2005's default Singleback playbook."

This distinction matters because:
- Generic plays will work in any compatible game's editor (universal football is universal)
- Madden-canonical plays would let you say "this is exactly what the Patriots playbook in Madden 06 has under 'Singleback Trio' → 'Mesh Strong'"

### 2. Madden-canonical plays (currently zero)

Plays extracted from a specific title's actual built-in playbook. These would carry:
- A `source_game:` field naming the title (e.g. `madden-05-ps2`)
- A `source_playbook:` field naming the in-game playbook (e.g. `Patriots Offense`)
- A `source_play_call:` field with the in-game call name (e.g. `Singleback Trio - Mesh Strong`)

None exist in the library yet. Adding them requires either manual extraction from the game or screenshot-based reconstruction.

## What `verification_status` means

The `verification_status` field on a play has values:

- **`unverified`** — the play hasn't been cross-referenced against a coaching reference or game playbook
- **`verified`** — the football concept (routes, blocking scheme, reads) has been validated against authoritative sources (cited in `source_notes`)
- **`inferred`** — the play was reasoned about from related plays / general principles, with explicit gaps

What `verification_status: verified` does **NOT** mean:
- It does **not** mean "this play is in Madden's built-in playbook."
- It does **not** mean "this play has been tested in the actual game's editor."
- It does **not** mean "every player position is in a legal Madden cell."

It only means: "the football concept this play describes has been sourced and is correct as football."

## Reading `source_notes`

The `source_notes` array on each play is a chronological log of what was sourced and when. Common patterns:

- `"Web validated YYYY-MM-DD — [source URL] — confirmed: [specific claim]"` — explicit web research
- `"Standard [scheme] coaching tradition; documented across [coaching tree]"` — claim of widespread documentation
- `"Built YYYY-MM-DD as part of the [phase] rollout"` — provenance breadcrumb when the file was authored
- `"Mirror of [original].yaml — path waypoints flipped on x; ..."` — auto-generated mirror breadcrumb

Always **append** to `source_notes`, never overwrite. The history matters.

## What to do with this distinction going forward

When you author a play through the MCPs:

- `build_starter_play()` produces a generic-football scaffold by default. The `source_notes` get a "Scaffold generated by build_starter_play()" breadcrumb that should be kept.
- If you're encoding a Madden-canonical play (extracted from a real game's playbook), add the source-game / source-playbook / source-play-call fields manually. The schema doesn't require them yet but accepts them under `source_notes`.

When you query the MCP and see `verification_status: unverified`, treat the play as "the football concept is correct but not double-checked, and not necessarily in any specific game's built-in playbook."

When you query for plays best vs a defense (`find_plays_vs_defense('cover-3')`), the rating is based on the play's documented `best_vs_defense` array — sourced from football coaching, not from gameplay simulation. A play that reads "best vs cover-3" will play well as football against any cover-3 defense, but may or may not be a viable in-game call depending on the specific game's AI / engine.

## Future schema additions

When a `source_provenance` schema is added, every play will get explicit fields:

```yaml
source_provenance:
  type: generic-football | madden-canonical | hybrid
  source_game: madden-05-ps2 | null
  source_playbook: "Patriots Offense" | null
  source_play_call: "Singleback Trio - Mesh Strong" | null
  source_references:
    - url: "https://..."
      claim_validated: "..."
      date: "2026-04-29"
```

Until then, `source_notes` is a free-text approximation. Be explicit when authoring.
