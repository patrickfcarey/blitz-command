# examples/

Reference SVG renders + click-by-click instructions for reproducing each play in a target game's editor grid. All current renders are against `madden-05-ps2`.

## Layout

```
examples/
  offensive-plays/       — single play SVG + .md instructions for create-a-play
  defensive-formations/  — single defensive formation with coverage zones (SVG only)
  matchups/              — offense + defense overlaid SVG + .md with matchup analysis
```

Each offensive play and matchup ships with a **`.md` companion** file containing step-by-step instructions for the in-game create-a-play editor: every player's exact `(col, row)`, every route's waypoint cells, QB drop path, blocking assignments, motion, and read tree. Generated by the `export_play_instructions` MCP tool — guaranteed to use only integer cells when the game profile sets `snap_to_cells: true` (Madden 05 does), and guaranteed conflict-free (no two players share a cell).

## offensive-plays/

18 offensive plays from a representative spread of formations:
- **Run** plays render with `--field short` (LOS+15yd) — box + deep DBs still on the green
- **Pass / PA / RPO** plays render with `--field long` (LOS+30yd) — shows deep routes

Filename convention: `<play-id>--<game-id>.svg`

Regenerate one:
```bash
.venv/bin/python tools/draw-play/draw.py --play singleback-trio-mesh --game madden-05-ps2 -o examples/offensive-plays/singleback-trio-mesh--madden-05-ps2.svg
```

## defensive-formations/

All 9 defensive formations rendered alone, with their coverage zones, rush arrows, and DB drops drawn from each defender's `responsibilities` entry. Goal-line uses `--field short`; everyone else uses `--field long` so the deep DBs are visible.

Filename convention: `<defense-id>--<game-id>.svg`

Regenerate one:
```bash
.venv/bin/python tools/draw-play/draw.py --defense defense-4-3-cover-3 --game madden-05-ps2 -o examples/defensive-formations/defense-4-3-cover-3--madden-05-ps2.svg
```

## matchups/

12 canonical play-vs-defense pairings — each chosen because it's a textbook example of the offensive concept either beating or struggling against the defense. The MCP `predict_matchup(play_id, defense_id)` rates each as best / neutral / worst with rationale, and these renders show why.

| Matchup | Why it's here |
|---------|---------------|
| Mesh vs Nickel Cover-1 | Anti-man rubs at the C — textbook |
| Flood vs 4-3 Cover-3 | 3-level stretch beats single-high — textbook |
| Smash vs 4-3 Cover-2 | Hi-lo on the playside corner — textbook |
| Stick vs 4-3 Cover-3 | Quick game with vertical clear |
| 4-Verts vs Nickel Cover-1 | Inner seam splits the FS |
| PA Cross vs 4-3 Cover-3 | PA holds LBs, TE wins underneath |
| HB Draw vs 4-3 Cover-2 | Constraint to passing — punishes pass rush |
| Power-O vs 4-2-5 Cover-2 | Gap run vs lighter nickel box |
| Counter Trey vs 3-4 | 2-pull misdirection vs odd front |
| Goal-line Power vs 6-2 stop | Short-yardage vs short-yardage |
| Triple Option vs 4-3 base | Option football vs base defense |
| QB Counter vs Cover-3 | Designed QB run vs base |

Filename convention: `<play-id>--vs--<defense-id>--<game-id>.svg`

Regenerate one:
```bash
.venv/bin/python tools/draw-play/draw.py \
    --play singleback-trio-mesh \
    --defense defense-nickel-cover-1 \
    --game madden-05-ps2 \
    -o examples/matchups/singleback-trio-mesh--vs--defense-nickel-cover-1--madden-05-ps2.svg
```

## Render modes

The drawing tool supports several other modes that aren't currently in `examples/`:

- `--show offense` — both teams visible, only offensive routes drawn (defense coverage hidden)
- `--show defense` — both teams visible, only defensive coverage drawn (offensive routes hidden)
- `--show none` — both teams visible, no assignments at all (just the pre-snap alignment)

Drop these into `examples/matchups/` with descriptive suffixes if useful.

## Bulk regeneration

To regenerate all example diagrams (e.g. after a renderer update):

```bash
# Offensive plays — see the loop in run-tests.sh or write a one-shot
for p in $(ls examples/offensive-plays/ | sed 's/--madden-05-ps2.svg//'); do
    pt=$(yq '.play_type' "data/plays/$p.yaml")
    field=$([ "$pt" = "run" ] && echo "short" || echo "long")
    .venv/bin/python tools/draw-play/draw.py --play "$p" --game madden-05-ps2 --field "$field" \
        -o "examples/offensive-plays/${p}--madden-05-ps2.svg"
done

# Defenses
for d in $(ls examples/defensive-formations/ | sed 's/--madden-05-ps2.svg//'); do
    field=$([ "$d" = "defense-goal-line-6-2" ] && echo "short" || echo "long")
    .venv/bin/python tools/draw-play/draw.py --defense "$d" --game madden-05-ps2 --field "$field" \
        -o "examples/defensive-formations/${d}--madden-05-ps2.svg"
done
```

Matchups need explicit pairing (no automatic enumeration since 144 plays × 9 defenses = 1296 SVGs).
